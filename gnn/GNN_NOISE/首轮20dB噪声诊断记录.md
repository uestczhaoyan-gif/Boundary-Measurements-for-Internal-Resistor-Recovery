# 首轮 20dB 噪声诊断记录

## 1. 实验口径
- 数据集：`data/training_data64Nodes_2.csv`（当前默认 `10mA`）
- 噪声设定：在 standardized 边界电压通道上注入高斯白噪声，`noise_std=0.1`
- 对应关系：按 `Noise_test.txt` 的口径，这相当于首轮 `20dB` zero-shot noise evaluation
- 随机种子：`20260331`
- 作用位置：仅测试集加噪；模型本身仍是 clean 数据训练得到的权重

  - `mask_prob` 整体抬升近一个数量级
  - 派生计数几乎全部塌到 `3`
  - 原本稀疏的边激活分布，被噪声直接推成了“全局过报”

## 3. 诊断：为什么 20dB 会让模型全面崩溃？

这绝不是 `o4a2` 或 `o5b` 这种局部架构设计的问题，而是 EIT（电学阻抗断层扫描）逆问题与生俱来的病态性（Ill-posedness）。

### 3.1 信号被完全淹没（The Signal-to-Noise Paradox）
- 你输入模型的是 standardized 的边界电压，整体尺度上 `std≈1.0`
- 这次加入的是 `std=0.1` 的噪声，表面看只是总幅值的 `10%`
- 但在 EIT 里，一个内部 `50Ω` 量级的小电阻变化，传到边界电极后的有效特征 `ΔV`，往往只占总边界电压的 `1%`，甚至 `0.1%`
- 这意味着：
  - 绝对噪声虽然只有总电压的 `10%`
  - 但相对“真正用于定位变化的微小差分信号”来说，噪声可能已经大了 `10` 倍甚至更多
- 原本依靠极微小边界差异来定位内部变化的 GNN，此时看到的就不再是稳定的物理模式，而是一片足以淹没目标信号的雪花噪点

### 3.2 流形塌陷（Manifold Collapse）
- 当前 `CLS` 和 `REG` 都是在极干净的数据上训练出来的
- 为了把 clean 场景下的分数推到 `93+`，模型实际上把决策边界压得非常尖锐
- 一旦输入离开训练时的 clean manifold，模型就不再是在“熟悉的物理流形附近微调判断”，而是直接掉到流形之外
- 这时模型会出现典型的 out-of-distribution 胡言乱语：
  - `CLS` 的 `macro_f1` 从 `0.9075` 直接掉到 `0.1203`
  - `REG` 的 `mask_prob` 大面积抬升，计数塌成“几乎全判 3”

## 4. 当前结论
- 第一次 zero-shot 20dB 噪声测试已经明确说明：
  - 当前最佳 clean GNN 主线在带噪场景下没有鲁棒性余量
  - 继续只在 clean 数据上做结构微调，已经不足以解决问题
- 因此接下来必须正式进入策略 B：
  - 数据增强
  - 带噪训练
  - 用 clean 权重 warm start 做低学习率微调

## 5. 对下一步的直接指向
- 不从头训练
- 直接加载 clean 最优模型：
  - `GNN_CLS/modelo3`
  - `GNN_REG/o4a2`
- 在训练集上动态随机注入噪声
- 使用较小学习率（例如 `5e-5`）微调 `20~30` 个 epoch
- 目标不是继续死记 clean 电压浮动，而是逼模型转向更稳定、更鲁棒的拓扑与结构信息
